# 全局配置功能说明

## 功能概述

Closer Code 现在支持全局行为规范配置，允许你在所有项目中共享统一的行为规范。

## 配置文件位置

### 全局配置
- **路径**: `~/.closer-code/cloco.md`
- **作用域**: 所有 Closer Code 项目
- **优先级**: 低于项目级配置

### 项目配置
- **路径**: `./cloco.md`（项目根目录）
- **作用域**: 当前项目
- **优先级**: 高于全局配置

## 工作原理

当启动 Closer Code 时：

1. **读取全局配置**（如果存在）
   - 从 `~/.closer-code/cloco.md` 读取全局行为规范
   - 显示：`✅ 已加载全局行为规范: ~/.closer-code/cloco.md`

2. **读取项目配置**（如果存在）
   - 从当前项目的 `./cloco.md` 读取项目特定规范
   - 显示：`✅ 已加载项目行为规范: ./cloco.md`

3. **构建系统提示词**
   - 全局配置和项目配置都会被添加到系统提示词中
   - 两者不会互相覆盖，而是共同生效
   - 如果都不存在，使用默认行为规范

## 配置示例

### 全局配置示例 (`~/.closer-code/cloco.md`)

```markdown
# Closer Code - 全局行为规范

## 编码风格
- 使用 2 空格缩进
- 优先使用 const/let，避免 var
- 函数名使用驼峰命名

## 工具使用偏好
- 优先使用 bash 工具执行命令
- 使用 searchFiles 查找文件
- 使用 readFile 查看文件内容

## 代码审查要点
- 检查安全漏洞
- 确保错误处理完善
- 验证边界条件
```

### 项目配置示例 (`./cloco.md`)

```markdown
# 项目特定规范

## 架构约定
- 使用 MVC 模式组织代码
- 数据库操作使用 ORM

## 工作流程
- 提交代码前必须运行测试
- 使用 git flow 分支管理

## 团队规范
- 代码审查必须由至少 2 人完成
- 使用中文编写注释
```

## 使用建议

### 适合放在全局配置的内容
- 通用的编码风格
- 代码审查标准
- 工具使用偏好
- 响应格式要求
- 安全最佳实践

### 适合放在项目配置的内容
- 项目特定的架构约定
- 特定库的使用规范
- 项目内的工作流程
- 团队协作规范
- 项目特定的业务规则

## 测试验证

运行测试脚本验证配置是否生效：

```bash
node test/test-global-cloco.js
```

测试会检查：
- ✅ 全局配置文件是否存在
- ✅ 项目配置文件是否存在
- ✅ 配置是否正确加载
- ✅ 系统提示词是否包含配置内容

## 注意事项

1. **配置文件支持任何语言**（中文、英文等）
2. **配置实时生效**，无需重启
3. **如果配置文件不存在**，会使用默认行为（不会报错）
4. **项目级和全局级配置会同时生效**（不会覆盖）
5. **配置文件必须是 Markdown 格式**

## 升级说明

如果你之前使用项目级的 `cloco.md`，升级后：
- ✅ 项目配置继续有效
- ✅ 可以添加全局配置
- ✅ 两者会同时生效
- ✅ 无需修改现有配置

## 相关文件

- 全局说明: `~/.closer-code/README.md`
- 项目配置: `./cloco.md`
- 测试脚本: `test/test-global-cloco.js`
