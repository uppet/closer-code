# Dispatch Agent Batch 模式验证场景

> **目标**: 验证 dispatch_agent 在实际场景中的运行效果
> **日期**: 2026-01-27
> **测试方法**: Batch 模式

## 📋 测试场景设计

### 场景 1: 代码库结构分析
**目标**: 使用多个 agents 并发分析项目结构

**任务**:
1. 查找所有配置文件（*.json, *.yaml, *.toml）
2. 查找所有测试文件（test-*.js, *.test.js）
3. 查找所有文档文件（*.md）
4. 统计源代码文件数量（src/**/*.js）

**预期结果**:
- 4个 agents 并发执行
- 每个返回搜索结果
- 总耗时 < 100ms（使用缓存）

### 场景 2: 功能特性搜索
**目标**: 搜索项目中的特定功能实现

**任务**:
1. 搜索 "agent" 关键词
2. 搜索 "cache" 关键词
3. 搜索 "pool" 关键词

**预期结果**:
- 找到相关文件
- 返回匹配行数
- 缓存生效（第二次搜索更快）

### 场景 3: 依赖关系分析
**目标**: 分析项目的依赖关系

**任务**:
1. 查找所有 import/require 语句
2. 统计外部依赖
3. 生成依赖树

**预期结果**:
- 找到所有依赖
- 分类外部/内部依赖
- 生成依赖报告

## 🚀 执行命令

```bash
# 场景 1: 代码库结构分析
node dist/batch-cli.js "

1. 查找所有配置文件（*.json, *.yaml, *.toml）
2. 查找所有测试文件（test-*.js, *.test.js）
3. 查找所有文档文件（*.md）
4. 统计源代码文件数量（src/**/*.js）
"

# 场景 2: 功能特性搜索
node dist/batch-cli.js "
搜索以下关键词：
1. agent
2. cache
3. pool
"

# 场景 3: 依赖关系分析
node dist/batch-cli.js "
分析项目依赖关系：
1. 查找所有 import/require 语句
2. 统计外部依赖
3. 生成依赖树
"
```

## 📊 验收标准

- ✅ 所有 agents 成功执行
- ✅ 返回结果正确
- ✅ 缓存机制生效
- ✅ 并发执行正常
- ✅ 无内存泄漏
- ✅ 性能可接受
